# Publishing browser review from the platform

The production publisher deliberately waited for a desktop click for up to 30 minutes. Backend Uvicorn runs as SYSTEM, so that browser is not visible on the user's interactive desktop. Task 12312 uploaded but remained waiting; it was not evidence of successful publication or verified cart contents.

The review module keeps a reference to each publishing coroutine's own page in the existing single backend process. `/publish-review` displays active tasks, current screenshots, a verification checkbox, and a one-task confirmation action. The platform entry opens this page; no Windows desktop access is required. Snapshots remain available after submitting, including platform verification prompts. No cookies, browser profiles, or remote-debugging endpoints are exposed.

Confirmation requires a screenshot captured after the task becomes ready, a current random token valid for two minutes, and a one-use request protected by an async lock. A confirmation only signals the original coroutine. It clicks exactly one uniquely named enabled Publish button once and retains the existing platform-success redirect check. It never retries an ambiguous click automatically. The screen explicitly reports an indeterminate platform quick-check rather than treating it as a pass. The user reviews that state before confirming.

The production publisher/main differences are preserved by function-scoped source patches. The frontend production bundle is preserved; its HTML receives only a link. The corresponding Vue source includes the same entry for future builds. Screenshot sessions are intentionally memory-local: restart or finished/failed tasks show no live page and must be checked in the task list before retrying.
