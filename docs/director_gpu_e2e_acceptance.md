## 2. 只读验收步骤

1. 在控制面确认样本满足 `director_status != 2`，且源 MP4/SRT 可读；不要执行状态修复或重置。
2. 通过导演合成接口提交样本。请求必须包含远端 GPU 生成的配音与非空 timed ASS 字幕；控制面不得调用本地 ffmpeg/ffprobe。
3. 轮询导演任务，记录 `job_id`、各阶段时间戳和最终状态。只有 `subtitles_burned=true` 且 `tts_audio_mixed=true` 才允许进入完成态。
4. 调用 GPU 节点的 `/director-jobs/{job_id}/quality` 只读检查，保存脱敏 JSON 摘要：视频流数、音频流数、时长、分辨率、执行节点、检查时间。
5. 在 GPU 节点抽取至少一个字幕显示时间点的帧（例如首个 timed cue 的中点），由验收人确认画面中出现字幕；记录时间点和“可见/不可见”，不要上传包含敏感内容的帧。
6. 确认配音文件在 GPU 节点可解码，并且最终文件存在音频流；最终视频完整解码通过，时长满足发布门禁（当前策略为 15–300 秒且竖屏短边至少 1080）。

## 4. 部署与回滚

### 部署

1. 先部署 GPU worker，再部署控制面；确认 GPU worker 健康检查和 `remote-gpu` 执行节点可用。
2. 灰度运行一个未成功样本，完成本记录全部门禁后再扩大范围。
3. 观察导演任务失败率、质量门禁失败率和 GPU 磁盘空间；不要启用本地媒体 fallback。

### 回滚

1. 停止新导演任务提交，等待正在运行的 GPU job 完成或按现有运维流程取消。
2. 回滚控制面与 GPU worker 到上一已验证版本，保持数据库 schema 不变。
3. 重新执行只读健康检查；已成功视频不重跑、不清除、不回写状态。
4. 对回滚前失败的样本保留错误分类和 job 证据，待修复版本重新灰度验收。
