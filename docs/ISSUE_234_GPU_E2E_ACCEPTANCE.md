# Issue 234：字幕烧录与配音混音 GPU-only 验收

## 验收范围

只选择一个源 MP4 可读、SRT 非空且至少含一个有效 timed cue、转录已完成、目标 group/recording 尚未成功的最小样本。验收只读检查数据库和媒体；不得把验收样本写成成功状态，也不得重跑已成功视频。

记录 `group_id`、`recording_id`、源媒体文件名、验收时间（UTC）、部署版本/commit 和 GPU job id。凭据、令牌和主机敏感路径不得写入报告。

## GPU-only 验收步骤

1. 只读筛选候选：确认 `director_status != 2`，源 MP4 可读，转录完成，SRT 大小大于 0，并解析出 `start < end` 的 cue。
2. 运行现有导演流程，确认执行节点是 `remote-gpu`。控制面不得调用本地 ffmpeg/编码 fallback。
3. 保存 group、recording、job id、阶段时间戳和部署版本；日志不得包含凭据或主机敏感路径。
4. 使用 `ffprobe` 只读检查最终 MP4：必须有视频流和可解码音频流，时长大于 0，且音视频时长差符合发布门禁。
5. 在字幕 cue 覆盖期间抽取最终视频帧，人工或视觉确认字幕确实烧录到画面；同时确认 GPU job 的 `ass_content` 含非空 `Dialogue:` cue。只检查 ASS 文本不足以证明视觉烧录。
6. 用 `ffprobe` 检查独立配音可播放，并确认最终视频包含音轨。验收结束后按现有清理策略处理配音文件，不更新生产状态。

## 失败门禁

- 没有 timed subtitle cue：任务失败，不得产出或标记无字幕成片。
- 没有生成配音、配音为空或不可播放：任务失败，不得用源音频静默替代。
- 最终文件缺少视频流或音频流：任务失败，不得写入 `director_final_video` 或成功状态。

## 部署与回滚

部署：先发布 GPU 服务并确认 health/NVENC，再发布控制面；先执行 `scripts/qa.sh`，随后用未成功的最小样本执行本 runbook。部署期间不修改生产数据库状态。

回滚：停止新的导演验收任务，回退控制面和 GPU 服务到上一版本，保留失败 job 的只读日志与 GPU artifact；不要把失败样本强制改成成功。已成功视频不重跑、不删除，恢复队列后只处理未成功样本。
