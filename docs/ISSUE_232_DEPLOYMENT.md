# Issue 232 发布时长门禁变更

## 变更范围

- 发布质量门禁统一使用 `backend/duration_policy.py` 中的 15 秒下限和 300 秒上限。
- 源视频、远端 GPU-only 媒体策略和现有分辨率检查不变。
- 前端创建发布任务提示与后端错误提示均说明 `15–300 秒`。

## 部署前备份

在远端应用工作目录执行备份，保留原文件权限和时间戳：

```sh
backup_dir="backups/issue232_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$backup_dir"
cp -p backend/duration_policy.py backend/publish_scheduler.py "$backup_dir/"
cp -p frontend/src/views/Publish.vue "$backup_dir/"
```

不要修改或覆盖源视频；重新剪辑输出应写入独立输出目录，确认通过 `ffprobe` 和发布质量门禁后再替换发布任务引用。

## 验证

1. 运行 `bash scripts/qa.sh`，确认五个门禁通过。
2. 对 162.8 秒目标文件执行 `ffprobe`，确认存在视频流、分辨率符合现有要求且时长不超过 300 秒。
3. 调用发布质量门禁确认返回通过；再仅对该发布任务执行受控重试。
4. 检查其他任务的状态和视频路径未发生变化。

## 回滚

停止发布调度后，从备份目录恢复上述三个文件，重新运行 QA 和单文件质量检查，再恢复调度。回滚不需要修改数据库；如已更新单个任务的视频引用，仅恢复该任务原引用，禁止批量重置或重跑其他成功任务。

## 当前工作区限制

本代码工作树不包含远端 162.8 秒源视频或生产数据库，因此不会在开发机伪造输出、改写生产状态或执行真实发布。部署时应使用现有 GPU 剪辑流程对该单个目标重新生成版本，并保存 `ffprobe`、质量门禁和可播放性证据。
